# 威胁模型

本文件记录 LoadLoom 的信任边界与已评估的威胁，配套代码里的等价约束：
`crates/loadloom-core/src/engine.rs`（信任边界校验）、`rate.rs`（有界等待）、
`src-tauri/src/logging.rs`（输出编码）。

## 范围

只覆盖**本机进程内**的攻击面：IPC 载荷、远端响应与错误文本、以及用户自己键入的参数。
不覆盖：被测试目标的安全（那是对方的责任）、操作系统的完整性、
恶意本地用户（能改写二进制的人已经赢了）。

## 资产

| 资产 | 为什么值得保护 |
| --- | --- |
| 用户对第三方的**授权边界**（并发数、限速、自动停止） | 这是本工具唯一的合法性依据。约束失效意味着可能产生远超授权的流量，带来法律与合同风险 |
| 本机资源（线程、内存、网络连接、磁盘日志） | 被畸形输入拖垮或挂死，等于工具不可用 |
| 日志的**可信度** | 崩溃与拒绝的唯一事后证据；被注入的日志会误导排障 |
| 进程存活 | 崩溃会丢掉全部现场线索（窗口直接消失） |

## 信任边界

```
用户键入 ──▶ WebView（前端）──IPC──▶ src-tauri Command ──▶ loadloom-core
                                       ▲
                            信任边界在这里，不在前端
```

**前端不是信任边界。** 任何前端校验都只是用户体验；`start_run` / `set_live_config`
是 IPC Command，可以被任意前端代码、开发者工具或进程内调试直接调用。
因此所有校验都在 `loadloom-core` 内部完成。

### 攻击者可控的输入

| 输入 | 载体 | 可能被用来做什么 | 现在的处理 |
| --- | --- | --- | --- |
| `url` | `StartRunRequest` | 让工具连接任意主机与端口 | 只接受 `http://` / `https://` 前缀；非空。**不做**私网地址过滤（见「已接受的风险」） |
| `threads` | 同上 | 超出授权的并发 | `clamp(1, MAX_WORKERS=32)` |
| `rate_mib` | 同上 | 极小正值触发等待溢出；`NaN` 静默关闭限速 | 非有限值拒绝；有限值 `clamp(0, 4096)`；等待时长有界且封顶 5s |
| `limit_gb` / `limit_minutes` | 同上 | 溢出成 `inf`，让「安全停止」永不触发 | 非有限值拒绝；收敛到 1 PiB / 约 1 年，被收敛时记 Warn 日志 |
| `authorized` | 同上 | 绕过授权门禁 | 必须为 `true`，否则 `NotAuthorized` |
| `patch.threads` / `patch.rate_mib` | `LiveConfigPatch` | 同 `rate_mib` | 同上；非法值返回 `CoreError` 而不是静默忽略 |
| 远端响应体与错误文本 | HTTP 响应 | 日志注入（伪造日志行）、超长行 | 控制字符转义 + 截断 2000 字符（CWE-117） |
| 远端响应体长度 | HTTP 响应 | 巨大响应块放大等待计算 | 令牌债务封顶一个桶容量，等待封顶 5s |

## 威胁与对策

| # | 威胁 | 影响 | 对策 |
| --- | --- | --- | --- |
| T1 | 畸形 `rate_mib` 触发 `Duration::from_secs_f64` panic | worker 静默消失，打流能力下降且无任何提示 | 唯一的 `wait_from_seconds`：非有限/非正数归零、超限封顶；`bucket.reserve` 为纯计算，可直接单测 |
| T2 | `stop()` 后立即 `start()`，退避中的旧 worker 复活 | 实际并发超出授权值；流量继续打向已叫停的目标 | 运行代次（`Control::run`）；`start`/`stop` 各递增一次；退避切片内也校验代次 |
| T3 | 自动停止阈值溢出，守卫永不触发 | 无上限流量（法律风险） | 阈值收敛到可达上限；`MAX_LIMIT_GB * GIB < u64::MAX as f64` 由单测钉住 |
| T4 | `NaN` 静默关闭限速或自动停止 | 同上（失效方向是最危险的一侧） | 非有限值一律拒绝，并通过日志与 `run_event` 广播 |
| T5 | 日志注入 | 伪造日志行，误导排障与责任认定 | 输出编码 + 长度上限；编码点唯一（`logging::write`） |
| T6 | HTTP 客户端构建失败时丢掉超时 | 源站不响应即永久挂死 | 降级到保留超时的最小配置并上报；都失败时 `start()` 明确拒绝 |
| T7 | 32 个 worker 同步重试（惊群） | 对不健康的源站雪上加霜 | 指数退避 + 按 worker 抖动（splitmix64，无需 `rand`） |
| T8 | 在途计数下溢 | 界面显示「在途 42 亿」，指标不可信 | 饱和加减（`request_started` / `request_finished`） |
| T9 | CI 工作流权限过大 | 被注入的 workflow 改动可写仓库 | `permissions: contents: read`（`release.yml` 才需要 `contents: write`） |

## 已接受的风险（有意不修）

| 风险 | 为什么不修 |
| --- | --- |
| 不限制目标地址为公网 | 这是压测工具的**功能**：允许指向内网、回环与自建服务。授权由使用者负责，`authorized` 门禁与 README 的授权声明承担告知义务 |
| 不限制单个响应体大小 | 压测需要真实压满目标，截断响应会改变被测系统的行为。内存风险由「读多少算多少、不缓冲整个响应体」的流式处理承担 |
| 计数器在新一轮 `start()` 时归零，上一代在途请求的收尾可能落进新计数 | 影响面是「统计口径」而非安全；彻底解决需要给计数器打代次，收益不值复杂度 |
| `open_log_dir` 调用 `explorer` | 参数是进程内部派生的路径（非用户输入），且 Windows 上 `Command::arg` 不经过 shell，无注入面 |
| 限速低于约 2.6 KiB/s 时实际速率会高于标称值 | 等待被 5s 封顶，这是「可中断」优先于「精确限速」的有意取舍；标称速率在这个量级已无实际意义 |
| 广播通道在还没有订阅者时会丢弃消息 | `Engine::spawn()` 期间桌面壳尚未订阅日志流，该窗口内的日志本就没有接收方。需要用户看到的告警（例如 HTTP 客户端降级）因此**刻意留到第一次 `start()`** 播报，而不是发出去就丢 |

## 已知缺口

- `get_log_path` / `open_log_dir` 两个命令已在壳内实现，但 `src/bindings.ts` 尚未
  暴露，界面还没有「打开日志」入口 —— 用户暂时只能自己去 `%LOCALAPPDATA%\LoadLoom\logs`。
- 契约镜像靠 `contract_wire` 测试守护，尚未由 `tauri-specta` 生成（上游未发稳定版）。
